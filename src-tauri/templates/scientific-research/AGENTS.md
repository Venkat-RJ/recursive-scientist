# Research project instructions

Read `main.md` and the relevant linked evidence before investigating, including in a fresh conversation. Use Lattice's Scientific Research Authoring skill when available.

Before proposing hypotheses or running experiments, use `prior_knowledge_read` to inspect the project's existing methods, evidence, comparisons and unresolved questions. Investigate missing evidence with Lattice's Papers and Literature tools and past experiment records. Use `prior_knowledge_write` to record source-grounded findings. Refer to findings by ID and revision in `main.md` and related research tools.

Before running an experiment, write a stable hypothesis ID, its prediction, and a falsification criterion in `main.md`. Describe the comparator, inputs, constraints, and intended run. Keep hypotheses and predictions distinct from observations and conclusions.

After running, give each attempt a stable experiment ID and link its exact code or Git revision, output, and observations. Retain failed, interrupted, and inconclusive attempts and contradictory evidence. Do not overwrite earlier outcomes or treat synthetic or training evidence as held-out validation.

Update Current Understanding and Next Investigation from the evidence. Revise the plan when results change the priorities, and say why. Keep the notebook concise and link to detailed artifacts so another conversation can resume from files alone.

Use the project's existing tools and honor its evaluation and data boundaries. Follow the user's scope for execution and file changes.
